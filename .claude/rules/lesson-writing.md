# レッスン追加時のルール

このファイルは `src/lib/lessons.ts` を編集するときだけ読み込まれる。

## 最重要の大前提

- **学習者は非IT人材である。** エンジニアではなく、経営者・個人事業主・営業職・デザイナーなど、プログラミングやITインフラの知識がない人が主なターゲット
- IT用語を「知っている前提」で書いてはいけない。すべての概念は日常生活の例えで説明すること
- 「やったけど何が起きたか分からなかった」「用語が分からなくて読むのをやめた」を絶対に防ぐ
- 初級→中級→上級のステップアップ形式なので、前のレッスンで学んだことだけを前提知識としてよい

## 非IT人材に説明するときの原則

### 技術概念は必ず日常の例えで説明する
- サーバー → 「インターネット上にある、あなたのサイトを置いておく貸しロッカーのようなもの」
- デプロイ → 「作ったサイトをインターネット上に公開すること。お店で言えば "開店" にあたる」
- CDN → 「世界中にコピーを配置する仕組み。東京の人は東京のコピーから、NYの人はNYのコピーから読み込むので速い」
- 環境変数 → 「アプリに渡すメモ書き。パスワードのように秘密にしたい情報を安全に渡す方法」
- API → 「アプリ同士が会話するための窓口。郵便局の窓口のように、決まったルールでやり取りする」
- リポジトリ → 「プロジェクトのファイルをまとめて管理する場所。Google Driveのフォルダのようなもの」
- ビルド → 「開発中のコードを、公開できる形に変換すること。原稿を印刷所で本にするようなイメージ」
- 静的サイト → 「いつ誰がアクセスしても同じ内容が表示されるサイト。パンフレットのようなもの」
- 動的サイト → 「ログインした人によって表示が変わるサイト。Amazonのおすすめ商品のようなもの」

### サービスの比較は「何ができて何ができないか」を実例で
- 抽象的な機能名の羅列ではなく、「こういうことをしたいならA、こういう場合はB」と具体的なシナリオで説明する
- 「Serverless Functions」ではなく「サーバー側で動くプログラムを書ける機能（例：お問い合わせフォームの送信処理）」のように書く

### 設定ファイルは「なぜそれが必要か」から説明する
- いきなり設定の書き方を見せるのではなく、まず「もしこの設定がなかったらどうなるか」「どんな問題を防いでいるか」を説明する

## 各フィールドの書き方

### description（やる前の説明）
- 「何をするのか」「なぜそれをするのか」「実行後にどういう変化が見えるか」を必ず含める
- 準備手順がある場合は番号付きリストで書く
- 専門用語を使う場合は必ずカッコ書きで日常の例えを添える
  - 例: 「JSON（ジェイソン：設定ファイルなどでよく使われるデータの書き方）」
  - 例: 「コミット（現在の状態を記録すること。ゲームのセーブのようなもの）」
- 「右のファイルツリーで確認してください」のように、ダッシュボード上の操作誘導も入れる

### prompt / command（コピーして実行する指示）
- prompt: Claude Codeに貼り付ける自然言語の指示
- command: スラッシュコマンド（/init, /plan 等）
- どちらもコピーボタン付きのブロックでUIに表示される
- 長い指示は箇条書き形式にすると読みやすい

### afterNote（実行後の解説）
- 「裏側で何が実行されたか」を具体的に書く（例：「Claude Codeは mkdir コマンドを実行しました」）
- 結果の確認方法を書く（例：「ファイルツリーでクリックして中身を確認してみてください」）
- 専門用語の補足は【用語メモ】、追加情報は【豆知識】、試してほしいことは【確認してみよう】のラベルで書く
- 「次のステップ」への橋渡しも意識する

### why（学びのポイント）
- 「なぜこの操作が便利か」「実際にどう役立つか」を初心者目線で書く
- 技術の説明ではなく、Claude Codeを使う上での価値を伝える
- 身近な例えを使う（「ゲームのセーブ」「専門家を呼び出す」等）

### hint（ヒント）
- 行き詰まったときに見るもの。結論を端的に書く

## コース別のトーン

- **初級**: プログラミング経験ゼロを想定。用語は全て噛み砕く。操作手順は1ステップずつ丁寧に
- **中級**: 初級を終えた人を想定。基本用語は説明不要だが、新しい概念は初出時に解説
- **上級**: 中級を終えた人を想定。技術用語は使ってOKだが、初出の概念は必ず日常の例えを添える。「非ITの人にも分かる上級」を目指す
- **サクッと実践**: 技術知識ゼロの経営者・個人事業主を想定。技術の仕組みより「何ができるか」「結果の確認方法」に重点

## テンプレート

新しいレッスンを追加したら、対応する `templates/{lessonId}/` ディレクトリも作成すること。
テンプレートにファイルがある場合（既存コードを読ませる系のレッスン）は、テンプレートファイルも作成する。
